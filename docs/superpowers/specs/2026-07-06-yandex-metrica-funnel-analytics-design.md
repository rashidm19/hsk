# Yandex Metrica — general + funnel analytics

**Date:** 2026-07-06
**Status:** Approved (design), pending implementation plan
**Scope:** Install one Yandex Metrica counter site-wide for general analytics, and
instrument the acquisition funnel `landing → onboarding → auth → paywall → app`
with goals (incl. purchase revenue).

## Goal

Get end-to-end visibility on `www.hskprep.cc`:

1. **General analytics** — visits, traffic sources / UTM, geo, devices, depth,
   bounce, Webvisor session replay + click map, across **all** pages (SEO content
   pages included), from a single counter.
2. **Funnel analytics** — a conversion funnel over the 5 stages with ~10 goals,
   including a **purchase** goal carrying revenue (KZT) and plan id, so drop-off
   and revenue-per-stage are visible in Metrica's funnel report.

## Decisions (locked)

- **New counter**, created via the Metrica API for `www.hskprep.cc`, timezone
  `Asia/Almaty`.
- **Depth:** stage goals + key micro-conversions (~10 goals), not per-screen.
- **Webvisor ON** with form-content masking (record behaviour, not field values).
- **E-commerce ON:** `purchase` carries `order_price` in KZT + plan id.
- No consent banner (Kazakhstan audience).

## Current state (verified in repo)

- Static HTML/JS site; HTML is generated by `build.js` and committed; DigitalOcean
  App Platform auto-deploys `main` on push.
- **No analytics of any kind is installed** anywhere today.
- **No `Content-Security-Policy`** on any funnel page → `mc.yandex.ru` will not be
  blocked. (Re-verify at implementation time; add a note if a CSP is introduced.)
- Funnel wiring already partly present:
  - `onboarding.js` has an **analytics seam** `obTrack(event, params)` (line ~55),
    explicitly reserved "for GA4 + Yandex Metrika". It currently only `console.log`s
    under `window.OB_DEBUG`.
  - `obTrack(...)` is **already called** for: `begin_checkout`
    (`startCheckout` → `proceed`, with `{plan, value, currency}`), `purchase`
    (`finishSuccess`, with `{plan, value, currency, order_id}`),
    `payment_cancelled`, `checkout_duplicate_prevented`.
- `build.js` already injects site-wide `<head>` content via `injectTheme()`
  (dark-mode loader into every page). This is the exact mechanism to reuse.
- Funnel geography in code:
  - **Landing** = root `/index.html` (`landing.js`). CTAs navigate to `/quiz/`.
  - **Onboarding** = `/quiz/index.html`, a client-side state machine in
    `onboarding.js`. Screens `s0`–`s25`, swapped by `render(dir)` (line ~251) with
    the current screen id in `FLOW[state.idx].id`. **URL does not change per
    screen** → per-stage tracking must use JS goals, not pageviews.
  - **Auth** = email gate at `s17` (`renderEmail`/`renderCode`; OTP via
    `HSKAuth.signInWithEmailOtp` / `verifyEmailOtp`, Google via
    `HSKAuth.signInWithGoogle`) AND the standalone `/login/` page (`login.js`,
    OTP + password + Google, ends in `HSKAuth.routeAfterAuth`).
  - **Paywall** = `s22` (`sPaywall`), checkout modal `s23` (`openCheckout` →
    `startCheckout`), exit-intent `s24`, success `s25` (`sSuccess`). Confirmed
    payment resolves in `handlePaySuccess` → `pollSubscription` → `finishSuccess`.
  - **App** = `body.app` pages (`/exams/`, `/words/`, …). Onboarding handoff is to
    `/exams/`.

## Architecture

### Counter injection (site-wide) — `injectMetrika()` in `build.js`

Add a `METRIKA_ID` constant to `build.js` (single source of truth, like the
hard-coded domain) and a new `injectMetrika()` function modelled on `injectTheme()`:

- Walk every generated `.html` file and, idempotently (guard on the counter id
  string being already present), insert **before `</head>`**:
  1. The **standard async Metrica snippet** (`tag.js`, counter id = `METRIKA_ID`)
     with options: `clickmap:true, trackLinks:true, accurateTrackBounce:true,
     webvisor:true, ecommerce:"dataLayer"`, plus the `<noscript>` pixel.
  2. A tiny **global helper** so page scripts never need the id:
     ```js
     window.ymGoal = function (name, params) {
       try { if (window.ym) window.ym(METRIKA_ID, 'reachGoal', name, params || {}); } catch (e) {}
     };
     ```
- Placed **before `</head>`** (async, non-render-blocking) so it does not disturb
  the no-flash theme loader (must stay first) nor the auth-script ordering that
  `scripts/inject-auth.js` depends on (auth scripts sit after the theme loader).
- Call `injectMetrika()` next to `injectTheme()` at the bottom of `build.js`.
- Re-running `node build.js` stamps the counter into all ~599 pages → general
  analytics everywhere. Output is committed and auto-deploys.

Rejected alternatives: (B) hand-inject only into the 4 funnel pages — loses
general analytics on SEO pages and hand-edits get overwritten by the build;
(C) GTM container — overkill, still needs per-page injection.

### Event wiring — route the existing seam into `ymGoal`

- **`onboarding.js`**: change `obTrack(event, params)` to call
  `window.ymGoal(event, params)` (keep the `OB_DEBUG` log). In the bridge, map
  the revenue param: if `params.value` is set, pass `order_price: params.value`
  (and keep `currency`) so Metrica records goal revenue. Then add the missing
  stage emits:
  - `ob_start` — first render of `s0` (once per session).
  - `ob_email_view` — first render of `s17`.
  - `auth` — on OTP verify success (`renderCode` success path) and on the Google
    return. (`begin_checkout`, `purchase`, `payment_cancelled`,
    `checkout_duplicate_prevented` already emit — no change beyond the bridge.)
  - `paywall_view` — first render of `s22`.
  - Fire the render-driven goals from a single spot in `render()` keyed on
    `FLOW[state.idx].id`, de-duplicated per screen id per page load.
- **`landing.js`**: fire `ymGoal('landing_cta')` on click of the primary
  "start assessment" CTAs. CTAs are anchors/buttons pointing at `/quiz/`; attach a
  delegated `click` listener to elements linking to `/quiz` (fire before nav — the
  async beacon tolerates unload).
- **`login.js`**: fire `ymGoal('auth')` (and optionally `login_success` for the
  returning-user cut) right before/after `HSKAuth.routeAfterAuth` on the OTP-verify
  and password success paths.
- **`app_enter`**: no code — modelled as a **URL page-visit goal** (path contains
  `/exams/`) in Metrica, so it also captures returning users landing straight in
  the app.

### Goals (created via Metrica API)

| Goal id (JS event)          | Type        | Fires at | Funnel stage |
|-----------------------------|-------------|----------|--------------|
| `landing_cta`               | JS event    | `landing.js` CTA → /quiz/ | Landing |
| `ob_start`                  | JS event    | `s0` render | Onboarding |
| `ob_email_view`             | JS event    | `s17` render | Onboarding→Auth |
| `auth`                      | JS event    | OTP/Google/password success | Auth |
| `paywall_view`              | JS event    | `s22` render | Paywall |
| `begin_checkout`            | JS event    | `openCheckout`/`startCheckout` (exists) | Paywall |
| `purchase`                  | JS event    | `finishSuccess` (exists), `order_price` KZT + `plan` | Purchase |
| `app_enter`                 | URL visit   | path contains `/exams/` | App |

Auxiliary (not funnel steps, diagnostics): `payment_cancelled`,
`checkout_duplicate_prevented`, optional `login_success`.

**Funnel report:** after goals exist, assemble the ordered funnel
`landing_cta → ob_start → ob_email_view → auth → paywall_view → begin_checkout →
purchase → app_enter`. Prefer a Metrica **composite/step goal** if the API supports
step definitions; otherwise create the individual goals via API and build the
funnel in the Reports → Funnels UI (documented in the plan).

## Data flow

1. Any page loads → inline snippet boots `ym`, sends the pageview (general
   analytics) and defines `window.ymGoal`.
2. User advances through the funnel → page scripts call `ymGoal('<stage>')` at the
   hook points above; `purchase` additionally carries `order_price`/`currency`/
   `plan`/`order_id`.
3. Metrica aggregates goals → funnel + revenue reports.

## Error handling / edge cases

- `ymGoal` and the seam are fully `try/catch`-guarded; analytics never breaks the
  funnel or a content page.
- Snippet on JS-less SEO pages is inert beyond the pageview + `<noscript>` pixel.
- `purchase` fires only inside `finishSuccess` on a **confirmed** server
  entitlement (`subActive(sub)`), so timeouts/optimistic S25 do not over-count.
- Injection is idempotent (id-guarded) — safe to re-run `build.js` and
  `inject-auth.js` in any order.

## Verification

- Local: `preview_*` on the funnel pages; load with `?_ym_debug=1` and confirm in
  the console that pageview + each `reachGoal` fires with expected params; confirm
  no CSP/network errors to `mc.yandex.ru`.
- Metrica: confirm the counter receives hits and goals register (API goal list /
  dashboard) before closing out.
